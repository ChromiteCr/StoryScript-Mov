# S3 设计：风格化拆镜、润色、计划直接用剧本的演员表

日期：2026-09-29。用户已认可本设计（对话中确认），版本划分为 S3 → S3a → S3b。

## 背景

- 用户希望 AI 拆镜时有更多风格化设置、更高的产出自由度：摄影能力强的组可以要求高难度镜头。
- 风格可以来自内置预设，也可以由用户说出一个参考（例如某位导演某部影片的运镜），由服务器用本组自己的 key 发一个「风格研究」请求整理出来。
- 已有镜头要能「润色」：按风格和要求重写、优化、细化一个或多个镜头。
- 计划页要直接用剧本里已有的「角色 ↔ 演员姓名」对应，而不是再录一遍。用户的示例剧本「绳索」开头就有人物表，格式为「演员：角色：简介」。

## 约束（沿用，不变）

- 洁净室：代码、提示词、界面、测试数据里**不出现**真实导演、片名（用户已选择「按手法命名，名字由你输入」）。用户自己输入的参考只存在他们的项目数据里，研究结果一律标注「通用手法建议（未核实）」，不得编造具体影片的镜头、时间码。
- LLM 只输出语义枚举和短文本，经 zod 和业务校验；结果先进草案（INV-03），勾选后才写入。
- 每步最多外发 3 次（含重试），`maxRetries: 0`；新任务计入服务器版每组每日的文本模型次数。
- key 不进日志、草案、前端；服务器版出站仍只连公网 https（egress 守卫不变）。
- 演员姓名（多为同学真名）**不发给模型**：拆镜、润色、研究的提示词里只用角色名。
- `packages/core` 保持纯函数；测试按 AT 编号命名，用 FakeChat，不依赖网络。

## S3 风格化拆镜与风格研究

### 风格卡（StyleCard）
- 字段：`id`、`name`（≤24）、`summary`（≤80）、`grammar`（镜头语言：运镜、镜头、构图、节奏，≤800）、`bias`（偏好的景别/角度/镜头/运镜枚举数组）、`gear`（器材与人手，≤300）、`low_budget`（低成本替代，≤300）、`origin`（`builtin | custom | researched`）、`reference`（用户输入的参考原文，仅研究卡，≤200）、`unverified`（研究卡为 true）、`created_at`/`updated_at`（内置卡为 null）。
- 内置 8 张（`packages/core/src/presets/styles.ts`，原创文案，按手法命名）：
  赛道贴地（车载多机位与长焦压缩）、胶片史诗（大特写、对称与交叉剪辑）、手持纪实、一镜到底调度、静观留白、居中对称、惊悚压迫、青春明快。
- 本组的卡存在项目数据库新表 `style`；本组默认风格和默认难度存在 `kv`（键 `style_defaults`）。

### 难度（StyleLevel）
- `steady` 稳妥（默认）：手机、稳定器、三脚架即可完成；提示词与现在一致。
- `bold` 进取：允许长镜头调度、复杂走位、滑轨和摇臂；每个有难度的镜头写清器材与走位。
- `extreme` 挑战：按「摄影能力强、愿意冒险」设计：车拍、航拍、环绕、一镜到底、变焦推拉都可以，镜头可以更多更碎；每个高难镜头必须写器材、安全注意和低成本替代。

### 放开自由度
- `ShotFields` 新增可选字段 `camera_notes`（拍法说明：调度、走位、器材；提示词要求 ≤120 字，校验 >300 字给警告）。旧镜头没有这个字段，值为空时不写入，内容哈希不变。
- `Movement` 新增 `orbit`（环绕）、`aerial`（航拍）、`dolly_zoom`（变焦推拉）。画板、中文标签、分镜脚本导入词表、图像提示词同步。
- 拆镜提示词：没有风格、没有风格要求且难度为稳妥时，**消息与 breakdown-v1 逐字相同**（演示回放和评测不受影响）；否则使用 `breakdown-v2`：加入【风格】【难度】区块和新运镜、拍法说明；「宁可少而准」只在稳妥档保留；规则 8 保留（不得声称具体影片的镜头），风格文字只作数据。
- 拆镜请求 `BreakdownRequest` 新增 `style_id`（可空）和 `level`（默认 steady）；`reference_note` 上限 500 → 800，界面改称「风格要求」。

### 风格研究
- 新任务 `research_style`：输入 `reference`（≤200）和 `notes`（≤300）；输出 `StyleResearchOutput`（name、summary、grammar、bias、gear、low_budget、confidence `high|medium|low`、caveats[]）。
- 提示词要求：把参考整理成可执行的通用手法；不编造具体镜头、时间码、台词；不确定就降低 confidence 并写 caveats；name 用手法描述命名，不含人名和片名。
- 结果写草案（kind `style`），用户在风格库里查看、可改名和改写后「保存为风格卡」（origin `researched`，`unverified: true`，`reference` 为用户原文）。
- 研究用模型：设置 > 模型新增「研究用模型」（可选，不填用主模型）和「联网搜索」开关。联网参数按服务商地址决定：`dashscope.aliyuncs.com` → `enable_search: true`；`api.openai.com` 且模型名含 `search` → `web_search_options: {}`；其他服务商不支持，界面注明。服务商以 400/422 拒绝该参数时，去掉联网参数再发（仍在 3 次之内）。

### 界面
- 剧本页标题栏新增「风格」按钮，打开「风格库」抽屉：内置卡、本组卡（新建、编辑、删除）、设为默认、默认难度、研究新风格（输入参考 → 任务进度 → 审阅草案 → 保存）。
- 拆镜表单：风格（默认用本组默认）、难度（稳妥/进取/挑战）、风格要求（800 字）。外发说明写明风格文字也会发送。
- 镜头编辑器：机位组新增「拍法说明」。镜头行在动作下方显示拍法说明（有时）。

## S3a 润色

- 入口：镜头行菜单「AI 润色…」；镜头编辑器「AI 润色…」按钮；镜头表「选择」模式（每行复选框、每场「全选本场」），选择栏「AI 润色（N）」。一次 1–12 个镜头，可跨场；锁定镜头不可选。
- 请求 `PolishRequest`：`shot_ids`、`mode`（`refine` 细化 / `improve` 优化 / `rewrite` 重写）、`instruction`（≤500，可空）、`style_id`、`level`。
- 任务 `polish_shots`，提示词 `polish-v1`：每个镜头给出引用 `s1…sN`、场次标题、出处段落原文、当前字段（不含 source），以及前后镜头的一行摘要；模型输出 `{shots:[{ref, change_note, fields(不含 source)}]}`，一对一。
- 校验：每个 ref 恰好一次；字段基础校验（角色别名、手法、秒数）；细化模式改了景别/角度/运镜只给警告。source 由服务器用原镜头的值补回，模型改不了出处。
- 草案 kind `polish`，scope `{shot_ids, expected_revisions, mode, instruction}`。
- 应用 `POST /api/v1/drafts/:id/apply-polish {selected, expected_revisions}`：逐个原位更新（revision+1，修订 origin `ai`，原因「AI 润色（细化）：要求…」），跳过锁定镜头，版本冲突返回 409。
- 审阅对话框：逐镜头「改前 / 改后」，改动字段高亮，附模型的改动说明，勾选后应用。

## S3b 计划直接用剧本的演员表

- `Entity` 新增 `actor_name`（可空，≤40）。迁移 3：加列；按现有演员资源回填（一个角色恰好被一个演员资源饰演时）。
- 角色编辑器新增「演员」；列表在角色名旁显示演员。
- 人物表识别（core 纯函数 `readCastList`）：在第一场之前的段落里找「人物：/人物表/角色表/演员表/主演」等标题后的行，或含「饰」的行。支持「演员：角色：简介」「角色：演员」「演员 饰 角色」「角色（演员 饰）」「角色——演员」。哪一边是角色由已有角色的名字或别名决定（完全相同 > 别名 > 近似：包含或只差一个字）；另一边是演员。
  - 某个**别名**在人物表里由另一位演员饰演（例如「伊柳沙长大后」），建议把它拆成单独的角色。
  - 找不到对应角色的行列出来，可选择新建角色（默认不勾）。
- 角色面板在有建议时提示「剧本的人物表写了 N 位演员」→「填入演员…」对话框，勾选后应用。
- 计划同步（core 纯函数 `planCastSync`）：按角色的演员姓名（按 `、，,;；/` 拆分）生成演员资源的新增/更新预览：同名演员合并，给他补上角色；剧本说由别人演的角色，从原演员资源移走。没写演员的角色不动。剧本地点（没有场地资源对应的）生成场地资源。新建的资源没有时间限制（沿用剧组时间），标为待确认。
- 计划页资源面板顶部：剧本和计划不一致时提示「同步…」，对话框显示预览，确认后应用。
- 通告单与打印：演员一栏显示「演员（饰 角色）」。

## 测试

- core：风格预设、v1 逐字不变（快照）、v2 区块、研究/润色提示词、`readCastList`（覆盖「绳索」式人物表，用原创人名）、`planCastSync`、新运镜的画板标记。
- server：风格 CRUD 与默认、研究任务（FakeChat，联网参数被拒后回退）、拆镜 v2 请求、润色任务与应用（锁定、冲突、source 不变）、配额计入、迁移 3 回填、人物表建议与应用、计划同步。
- web：风格库、拆镜表单、选择模式与润色对话框、演员字段与同步对话框（单元 + e2e）。
- 不做压测。
