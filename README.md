开源、在本地运行的**实拍分镜工作台**。

它把剧本拆成有出处、可以锁定的镜头表，并为每个镜头自动画出带真实焦段和机位的宽银幕铅笔分镜，不需要任何 API key。它还能排出经过校验的拍摄顺序，让你在现场快速记录条次。拍完之后，实拍素材挂回同一个镜头 ID，漏拍了什么一眼就能看到。

> **v0.1 开发预览版**：还没有经过真实剧组试拍。功能边界见下方"功能现状"。规格见 [docs/SPEC-v0.1.md](docs/SPEC-v0.1.md)，计划见 [docs/PLAN.md](docs/PLAN.md)。

## 它能做什么

- **剧本进，镜头出**
  - 支持粘贴或导入 `.txt`、`.md`、`.fountain`，按场景标题规则切场，每个段落都有锚点。
  - AI 按场拆镜，先生成草案，你逐条勾选后才写入；每个镜头都回链剧本原文，引用对不上的条目不能应用。
  - 锁定的镜头，AI 永远不改。
  - 没有 key 时，可以全程手工建镜头。
- **宽银幕铅笔分镜，开箱即用**
  - 镜头一写入，就按世界坐标相机模型自动出图：景别、焦段、机高、俯仰都有真实的物理含义。
  - 取景框和俯视站位图出自同一份数据。
  - 画风是确定性的铅笔稿：先铺明暗再描线，排线统一方向，轮廓收尖。同一个镜头每次画出来都一样，不调用任何图像模型。
  - 画布上可以直接拖动人物站位和运动箭头，支持撤销和版本历史；导出为分镜 PDF 或单格 PNG。
- **改的是镜头语法，不是滤镜**
  - 手法模板（对话覆盖、双线交叉、悬疑揭示）和外观预设"宽银幕铅笔分镜"，直接改变机位与构图的默认值：尺度大全景、视点纪律、面孔特写、多画幅中心保护线。
- **拍摄顺序有独立校验**
  - 包括资源与选角、setup 自动分组、时间窗与约束。
  - 排期结果全部要过一个独立的校验器：只有存在明确矛盾时才会说"排不出来"，并附上依据。
  - LLM 可以给出排序建议，但结论仍以校验为准；只有通过校验的计划才能批准。
  - 可导出拍摄单、打板卡和预填镜号的场记模板。
- **拍完找得到**
  - 现场用大字号镜号快速录入条次，一条可以覆盖多个镜头。
  - 素材只读导入：ffprobe 读元数据、抽海报帧、算 SHA-256，并检测文件是否被改动过。
  - 按打板码、机内文件名或自定义正则生成关联候选，全部由你审核确认。
  - 覆盖状态与漏拍清单（无场记、无关联、无已确认可用片段、文件离线）适用于所有镜头，包括无对白镜头、插入镜头和空镜。
- **AI 铅笔重绘（实验，BYOK）**
  - 以结构稿为参考构图，调用你自己配置的图像服务重画成铅笔质感。
  - 结果只作候选：用洋葱皮对比后手动采用，导出时带"AI 生成"角标。
  - 构图可能漂移；结构层永远不会被改写。

## 快速开始

需要 **Node.js ≥ 24.15**（推荐 `brew install node`，24 LTS 或 26 都可以）。素材导入另需 **ffmpeg / ffprobe**（`brew install ffmpeg`）；没装时应用照常运行，只是素材导入不可用。

```bash
npx storyscript-mov
```

终端会打印一条带一次性令牌的本地链接（`http://127.0.0.1:<端口>/#t=…`），浏览器会自动打开。只有带令牌的链接能进入；如果链接失效，运行 `npx storyscript-mov open` 重新打开。

从源码运行：

```bash
git clone <仓库地址> storyscript-mov
cd storyscript-mov
npm ci
npm start
```

其他命令：`npx storyscript-mov doctor` 检查运行环境；`npx storyscript-mov --demo` 打开演示项目，不需要 key，界面会常驻"演示回放，非真实模型输出"的提示。

> 如果坚持用 Homebrew 的 `node@24`：它是 keg-only 包，默认不会进入 PATH。需要按 `brew info node@24` 的提示把它加进 PATH，否则 `npx` 仍会用旧版 Node。

## 配置模型（BYOK）

所有模型调用都走你自己配置的服务。只有你点击 AI 按钮时才会外发，发送前会告诉你发送什么、发往哪里。

- **文本模型**（拆镜、实体抽取、排序建议）：OpenAI chat completions 兼容协议，在设置页填 `base_url`、`api_key`、`model`；也可以用环境变量 `STORYSCRIPT_LLM_BASE_URL` / `STORYSCRIPT_LLM_API_KEY` / `STORYSCRIPT_LLM_MODEL`（优先级高于设置页）。
  - 结构化输出按"json_schema → json_object → 纯提示"逐级降级，并记住每个服务支持哪一级。
  - 每步最多外发 3 次，网络重试也计在内。
- **图像模型**（AI 铅笔重绘，实验）：同样填三项，应用会按服务地址自动识别接口写法：
  - 默认是 OpenAI 标准的 `/images/edits`；
  - 火山方舟 Seedream 与 OpenRouter 使用参考图写法的预设；
  - Gemini 与百炼的兼容地址会提示"不能用于草图重绘"。

  所有组合目前都是"未验证"，详见 [docs/providers.md](docs/providers.md)。

API key 只保存在本机的 `~/.config/storyscript-mov/credentials.json`（权限 0600）或环境变量里，不会写入项目、日志、导出文件，也不会发给前端。费用以服务商账单和返回的 usage 为准。

## 隐私与安全

- 服务只监听 `127.0.0.1`。令牌换成 HttpOnly cookie，并校验 Host 与 Origin，防止其他网页读取你的本地数据。
- 原片只读：派生文件（海报帧等）只写进项目目录，源目录不会多出任何文件。
- 发给模型的内容只有你点击时选中的剧本段落，或分镜的控制图与镜头描述，不会发送原片。

威胁模型与漏洞报告方式见 [SECURITY.md](SECURITY.md)。

## 常见问题

- **为什么要自己装 ffmpeg？** 为了保持许可证清晰（MIT），本项目不打包 ffmpeg，只以子进程方式调用你已经安装的版本。
- **为什么 ProRes、10-bit 素材不能直接播放？** 浏览器解不了这些编码。v0.1 只显示海报帧和元数据，按需生成代理放在 v0.2。
- **铅笔稿能保证和 AI 图一样好看吗？** 不能。确定性铅笔稿保证构图与镜头数据一致，可以复现，但没有插画级的细节。AI 重绘的质感更像手绘，但构图可能漂移，需要你对照后再采用。
- **为什么叫"开发预览版"？** 按规格，只有完成一次真实小拍摄的全流程验证后，才能去掉这个标签。

## 灵感与参考

宽银幕铅笔分镜风格的灵感，来自公开出版的电影剧本书中动作场面铅笔分镜的常见特征，也包括克里斯托弗·诺兰曾强调的"an absolute concern with point of view"（DGA Quarterly, 2012）。本项目与克里斯托弗·诺兰、其合作分镜师、Syncopy、华纳兄弟及 IMAX Corporation 均无关联，未获其认可或授权。仓库不含任何分镜原稿、剧照或描摹；所有模板、人偶、样例剧本和纸纹都是原创或程序生成的。

## 开发

```bash
npm ci
npm test            # vitest
npm run typecheck   # 依次检查 core（不带 Node 类型）、server 与测试、web
npm run dev         # 开发服务器（Vite middleware，端口 4700）
npm run look        # 渲染 12 个标准镜头并输出画风指标
npm run e2e         # Playwright 端到端测试（需要本机 Chrome）
```
